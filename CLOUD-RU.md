# Битва коммерсантов — запуск на Cloud.ru

Это облачный вариант викторины для двух независимых учебных классов с подключением по HTTPS/WSS без внешних MQTT-брокеров.

## Что подготовлено в GitHub

- `Dockerfile` в корне — образ для Cloud.ru Container Apps, Node.js 22, порт 8080.
- `lan-server/server.js` — одновременно раздаёт страницы и обеспечивает обмен сообщениями через `/ws`.
- В браузере автоматически используется `?lan=1`, поэтому соединение идёт с тем же облачным адресом, а не с зарубежными MQTT-серверами.
- `/healthz` — endpoint для проверки состояния контейнера, ответ `{"ok":true}`.
- `lan-server/load-test.mjs` — проверка до 200 имитированных подключений, без личных данных.

## Быстрое развёртывание через Workflow Studio

1. Войдите в https://console.cloud.ru и проверьте условия бесплатной квоты и контроль расходов.
2. Откройте **Разработка → Workflow Studio → Services → Мои сервисы → Создать сервис**.
3. Выберите **Другой Git-провайдер**, репозиторий `https://github.com/poddon/opp-quiz`, ветка `main`.
4. Название, например: `opp-commercial-quiz`.
5. Запустите создание сервиса. Workflow Studio должен собрать Dockerfile из корня, создать образ и Container App.
6. После сборки откройте выпущенный публичный HTTPS-адрес.
7. При необходимости в **Container Apps → Container Services** проверьте порт **8080**, включённый **Публичный адрес**, **выключенную авторизацию Cloud.ru** (иначе студентам понадобится аккаунт Cloud.ru), **максимум экземпляров 1**, **минимум 0** для экономии ресурса.
8. Для долгих занятий рекомендуем увеличить `Request-таймаут` (по умолчанию 600 с) до максимума, который разрешён интерфейсом. При обрывах интерфейс автоматически переподключается.
9. Для настройки health-проб используйте GET `/healthz`.

Официальная инструкция: https://cloud.ru/docs/tutorials-evolution/list/topics/container-apps__deploy-app-with-workflow

### Почему именно 1 экземпляр

В учебной версии сообщения об игре и подписки участников хранятся **в оперативной памяти** Node.js. Несколько параллельно работающих экземпляров не делят это состояние друг с другом. Максимум 1 сохраняет работоспособность двух комнат на одном сервере.

При перезапуске контейнера публикации из памяти исчезнут; преподавателю следует оставить вкладку ведущего открытой — его результаты сохраняются в браузере. Для постоянного серверного хранения нужен дополнительный бэкенд/БД.

### Ссылки после запуска

Пусть адрес контейнера, показанный Cloud.ru, будет `https://ВАШ-АДРЕС`. Тогда:

- Класс 1, студенты: `https://ВАШ-АДРЕС/?room=class1&lan=1`
- Класс 2, студенты: `https://ВАШ-АДРЕС/?room=class2&lan=1`
- Экран ведущего 1: `https://ВАШ-АДРЕС/screen.html?room=class1&lan=1`
- Экран ведущего 2: `https://ВАШ-АДРЕС/screen.html?room=class2&lan=1`

Откройте сначала экран ведущего соответствующего класса, затем покажите QR-код на проекторе. QR будет вести на тот же Cloud.ru, без GitHub Pages.

**Не используйте старые QR с `poddon.github.io` для занятий через Cloud.ru:** они обращаются к другой версии сервиса и другим каналам связи.

## Нагрузочный тест

На компьютере с Node.js **22+**:

```bash
node lan-server/load-test.mjs wss://ВАШ-АДРЕС/ws 50
```

Тест открывает 51 соединение (50 студентов + ведущий), проверяет полученные состояния, регистрации и подтверждения. Для теста используется отдельная случайная тема, он не изменяет реальные игры.

Успешный тест с одного ноутбука — лишь первая проверка, затем проверьте вход на реальных телефонах из корпоративной Wi-Fi-сети **без VPN**, в браузере, которым пользуются колледжисты.

## Бесплатный лимит и возможные расходы

Cloud.ru Container Apps free tier: **25 vCPU·ч и 50 ГБ RAM·ч на месяц для Container Services**. Это не безлимитный бесплатный хостинг. Например:

- При 0.1 vCPU / 0.25 ГБ — ориентировочно до 200 часов ресурса в месяц по RAM при условии, что остальные потребители квоты отсутствуют.
- При 0.5 vCPU / 0.5 ГБ — ориентировочно до 50 часов в месяц по CPU.

Фактическая тарификация зависит от реального использования и действующих условий Cloud.ru. **Workflow Studio и Artifact Registry могут тарифицироваться отдельно** (сборки, шаги, хранение образов), даже если Container Apps укладываются в бесплатную квоту.

Перед запуском проверьте в личном кабинете **Контроль затрат / бюджет / уведомления**, а также способы отключения приложения. Не привязывайте карту и не используйте платные услуги, пока не согласованы лимиты.

## Доступ и персональные данные

У этого прототипа не включена авторизация ведущего, а участники вводят фамилию и имя. При размещении в публичном интернете доступ к управлению и видимым именам открыт всем, у кого есть адрес. **Не публикуйте ссылку открыто**, не используйте для официальных персональных данных без одобрения организации и доработки авторизации. Публичная ссылка — не защита.

Если нужен гарантированно бесплатный вариант в корпоративной Wi-Fi-сети, используйте `lan-server/start.bat`: компьютер преподавателя вместо Cloud.ru.
